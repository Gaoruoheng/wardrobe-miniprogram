# 套装功能设计

日期：2026-08-04

## 1. 目标

为每个衣柜增加可长期保存、可重复使用的“套装”模板。用户可以把多件现有衣物保存成套装，并将套装一键合并到当前拿衣清单中。

成功标准：

- 用户可以从当前拿衣清单快速保存套装。
- 用户可以通过独立编辑页创建和修改套装。
- 衣柜内所有成员都能查看、创建和使用套装。
- 使用套装不会清空当前拿衣清单，也不会加入重复或正在使用中的衣物。
- 衣物失效、共享冲突和网络失败都有明确反馈，且不会破坏已有选择。

## 2. 范围与非目标

### 本期范围

- 套装列表、空状态、加载状态和异常状态。
- 快速保存套装。
- 独立创建和编辑套装。
- 套装详情、使用、编辑和删除。
- 共享成员权限校验。
- 云端原子合并到拿衣清单。
- 本地缓存同步和必要的自动化测试。

### 本期不做

- 按日期安排穿搭。
- AI 自动搭配或搭配评分。
- 向衣柜以外的用户公开套装。
- 单独上传套装封面。
- 套装收藏、点赞、评论或使用历史。
- 拖拽调整套装展示顺序。
- 替换或清空当前拿衣清单。

## 3. 核心概念

- **拿衣清单**：当前临时需要取用的衣物集合。
- **套装**：由多件衣物组成、长期保存且可以反复使用的模板。
- **使用套装**：保留当前拿衣清单，把套装中可用且未重复的衣物追加进去。

两个概念在文案和数据上必须分离。保存套装不清空拿衣清单，使用套装也不修改套装本身。

## 4. 信息架构

保留首页现有“菜单、计划、任务、关于”标签，不新增顶部标签。“任务”页扩展为准备中心，并按以下顺序展示：

1. 当前拿衣包裹，沿用现有卡片和详情面板。
2. 我的套装，新增横向滚动套装卡片区。
3. 我的任务，沿用现有新增、完成和删除流程。

这样可以保持主页面骨架不变，并把长期模板与临时拿衣行为放在同一任务上下文中。

## 5. 用户流程

### 5.1 从拿衣清单快速保存

1. 用户在菜单中选择至少两件衣物。
2. 用户打开现有拿衣清单面板。
3. 面板操作区显示“清空清单”“存为套装”“保存清单”。
4. 点击“存为套装”后打开轻量保存面板。
5. 面板自动带入当前衣物，展示前三件组成的拼图封面。
6. 用户填写必填套装名称，可选填写备注。
7. 保存成功后关闭轻量面板，拿衣清单保持原样，新套装出现在“我的套装”首位。

当清单少于两件时，“存为套装”仍可点击，但点击后给出“至少选择两件衣物才能保存套装”的就地提示。

### 5.2 独立创建套装

1. 用户在“我的套装”标题右侧点击“＋ 新建”。
2. 进入独立套装编辑页。
3. 顶部填写套装名称和可选备注。
4. 中部按现有衣物分类展示可选衣物。
5. 用户勾选衣物时，顶部实时更新已选数量和自动拼图封面。
6. 底部固定“保存套装”按钮，适配键盘和底部安全区。
7. 保存成功后返回任务页，并将新套装放在列表首位。

### 5.3 查看和使用套装

1. 用户点击套装卡片，打开套装详情面板。
2. 面板展示名称、备注、全部衣物、状态提醒和创建者。
3. 用户点击“一键加入清单”。
4. 云端读取最新拿衣清单并执行原子合并。
5. 客户端更新拿衣包裹和套装详情，并显示结果摘要。

示例结果：`已加入 3 件，跳过 1 件重复衣物，1 件正在使用中未加入。`

### 5.4 编辑和删除

- 创建者或衣柜主人可以从详情面板进入编辑页。
- 创建者或衣柜主人可以删除套装，删除前必须二次确认。
- 其他共享成员可以查看和使用，但不显示编辑、删除操作。
- 删除套装不会删除其中任何衣物，也不会更改当前拿衣清单。

## 6. 页面与组件设计

### 6.1 “我的套装”区

- 标题左侧显示“我的套装”，右侧为“＋ 新建”。
- 无套装时显示：`还没有套装，从当前拿衣清单保存一套吧。`
- 套装较多时使用横向滚动，不增加任务页首屏高度的无限增长。
- 每张卡片显示：自动拼图、套装名称、衣物数量、创建者和状态提醒。
- 卡片整体可点击，主操作放在详情面板中，降低误触概率。

### 6.2 套装卡片

- 延续现有公主城堡/月宫卡片语言，不建立新的视觉主题。
- 封面使用最多三件衣物的缩略图拼图；不足三件时使用现有柔和底纹补位。
- 名称最多显示两行，超出后省略。
- 衣物失效时显示“需整理”状态，不把警告做成阻断式红色大面积提示。
- 已收纳衣物只显示柔和提醒，仍允许使用套装。

### 6.3 套装详情面板

- 复用现有底部面板交互和安全区处理。
- 顶部：套装名称、备注、创建者、关闭按钮。
- 中部：衣物列表和状态标记。
- 底部主按钮：“一键加入清单”。
- 有权限时提供次要操作：“编辑套装”“删除套装”。

### 6.4 套装编辑页

- 使用现有自定义顶部导航和返回按钮。
- 名称必填，最多 20 个字符；备注可选，最多 60 个字符。
- 已选预览始终显示当前数量，最多选 20 件。
- 衣物按分类展示并提供已选状态，不改变原有衣物状态。
- 保存按钮在保存期间显示“保存中”并禁止重复提交。
- 输入时保留页面内容，网络失败后允许直接重试。

## 7. 数据模型

新增独立集合 `wardrobe_outfits`：

```js
{
  _id: String,
  wardrobeId: String,
  name: String,
  note: String,
  itemIds: String[],
  coverItemIds: String[],
  createdByOpenId: String,
  createdByName: String,
  createTime: Date,
  updateTime: Date,
  version: Number
}
```

规则：

- `itemIds` 去重并保留用户选择顺序。
- `coverItemIds` 从有效 `itemIds` 的前三项生成，不允许包含额外衣物。
- 每套至少 2 件、最多 20 件。
- 每个衣柜最多 50 套。
- 默认按 `updateTime` 倒序展示，新建或编辑后的套装靠前。
- 衣物名称、图片和状态不复制到套装记录中，展示时读取衣物最新数据。
- `version` 用于编辑冲突检测，避免共享成员覆盖较新的修改。

## 8. 云端接口与数据流

在现有云函数入口中增加以下操作：

- `listOutfits(wardrobeId)`：返回当前衣柜套装摘要。
- `getOutfit(wardrobeId, outfitId)`：返回套装详情和最新衣物信息。
- `saveOutfit(wardrobeId, outfit)`：创建或更新套装，并校验数量、权限和版本。
- `deleteOutfit(wardrobeId, outfitId)`：仅创建者或衣柜主人可执行。
- `applyOutfit(wardrobeId, outfitId)`：在云端原子合并到拿衣清单。

客户端可以复用现有按 ID 获取衣物和衣物展示装饰逻辑。套装列表只加载摘要，打开详情时再补齐完整衣物数据。

### 8.1 原子合并算法

`applyOutfit` 必须在服务端完成：

1. 校验调用者有权访问衣柜。
2. 读取套装和衣柜最新 `selectedItemIds`。
3. 读取套装衣物的最新记录。
4. 将衣物分类为：可加入、已重复、正在使用、已删除、已收纳。
5. 保留现有清单顺序，再按套装顺序追加“可加入”和“已收纳”衣物。
6. 在事务中写回最新清单和更新时间。
7. 返回最终清单及各类跳过数量。

数据库事务发生冲突时由服务端进行有限重试；重试仍失败则不修改清单，并返回可重试错误。

## 9. 权限

- 所有衣柜成员：查看套装、创建套装、使用套装。
- 套装创建者：编辑和删除自己创建的套装。
- 衣柜主人：编辑和删除衣柜内任意套装。
- 其他成员：不能编辑或删除他人创建的套装。
- 所有权限必须在云端重新校验，不能只依赖客户端隐藏按钮。

## 10. 状态与异常处理

### 加载与空状态

- 首次加载显示套装骨架卡片或统一加载提示。
- 无套装显示引导文案和“新建套装”入口。
- 加载失败保留任务页其他内容，并提供“重新加载”。

### 衣物状态

- 重复衣物：跳过，不作为错误。
- 正在使用：不加入，结果摘要明确说明。
- 已收纳：允许加入，同时显示“含已收纳衣物”。
- 已删除或无权访问：不加入，套装卡片标记“需整理”。
- 套装只剩一件有效衣物：仍可查看、编辑和使用剩余衣物，同时提示套装需要整理；再次保存时必须补齐至少两件。

### 保存与并发

- 名称为空、少于 2 件、超过 20 件或超过衣柜套装上限时就地提示。
- 保存失败保留输入和选择，不自动关闭页面。
- 编辑版本冲突时提示“套装已被其他成员更新”，重新加载最新内容后再编辑。
- 使用套装失败不改变本地清单，并提供重试。
- 删除操作必须二次确认；删除失败时详情面板保持打开。

## 11. 缓存与性能

- 套装摘要按“用户＋衣柜”缓存，进入任务页可先展示缓存再静默刷新。
- 创建、编辑、删除后只更新对应套装缓存，不清空无关衣物缓存。
- 套装详情按需加载，避免任务页一次解码所有衣物图片。
- 拼图图片使用现有缩略图地址并启用懒加载。
- 套装衣物不参与主衣物列表的重复查询，优先复用当前衣柜缓存，缺失项再按 ID 补齐。

## 12. 可访问性与移动端适配

- 新建、关闭、使用、编辑和删除操作的有效触控区域至少约 88rpx。
- 套装状态不能只依赖颜色，必须配合明确文字。
- 底部面板和固定保存按钮适配 `safe-area-inset-bottom`。
- 输入框启用键盘避让，保存按钮不能遮挡名称或备注。
- 动画仅用于按压、面板进入和成功反馈，不使用持续漂浮或影响阅读的效果。
- 辅助文字保持足够对比度，并支持长名称省略而不挤压操作按钮。

## 13. 测试策略

### 单元测试

- 套装衣物去重和顺序保持。
- 合并算法对重复、使用中、已收纳和已删除衣物的分类。
- 每套 2–20 件和每衣柜 50 套限制。
- 权限判定：创建者、衣柜主人、普通共享成员。
- 版本冲突和事务重试结果。

### 接口测试

- 创建、读取、编辑和删除套装。
- 共享成员可查看和使用，但不能编辑他人套装。
- 两个成员同时使用不同套装时，最终清单不丢失任何有效选择。
- 衣物删除后详情与使用结果一致。

### 界面测试

- 快速保存和独立创建流程。
- 空、加载、失败、保存中和无权限状态。
- 套装详情面板和固定按钮安全区。
- WXML 标签嵌套、事件绑定和关键样式回归。
- 微信开发者工具中验证窄屏、长名称、20 件套装和 50 套列表。

## 14. 验收标准

- 当前拿衣清单至少两件时，可以在不离开面板的情况下保存为套装。
- 用户可以从独立页面创建、编辑 2–20 件衣物的套装。
- 套装对同一衣柜内所有成员可见。
- 普通成员无法编辑或删除他人套装，创建者和衣柜主人可以。
- 使用套装时现有清单保持不变，新增衣物按套装顺序追加。
- 重复、使用中、已收纳和已删除衣物都有正确处理和摘要反馈。
- 多人同时操作不会导致拿衣清单丢项或互相覆盖。
- 所有失败状态保留用户输入或已有清单，并提供可理解的恢复路径。
- 新界面延续现有公主城堡/月宫风格，不改变现有菜单、计划、任务和关于功能。
